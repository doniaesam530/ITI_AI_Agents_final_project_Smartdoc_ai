# SmartDoc AI — Lab 6 Cross-Course Capstone

A Documents API (Lecture 4/5 foundation) extended with Gemini-powered
structured document analysis and a read-only, whitelisted tool-calling
agent.

## 1. Install

```bash
pip install -r requirements.txt
```

## 2. Configure

Copy `.env.example` to `.env` and fill in your own key:

```bash
cp .env.example .env
```

```
GEMINI_API_KEY=your_real_key_here
GEMINI_MODEL=gemini-1.5-flash
DATABASE_URL=sqlite:///documents.db
```

`.env` is git-ignored — never commit your real key.

## 3. Migrate

This project ships with the same `documents.db` used in Lectures 3–5,
plus the Lab 6 migration already generated. To (re)apply it against your
own copy:

```bash
python -m alembic current       # see which revision you're on
python -m alembic upgrade head  # apply pending migrations, keeps existing rows
```

## 4. Run

```bash
uvicorn main:app --reload
```

Open:
- http://127.0.0.1:8000/docs
- http://127.0.0.1:8000/redoc
- http://127.0.0.1:8000/openapi.json

## 5. Test

**Automatically** (fills a full pass/fail matrix):
```bash
python run_contract_tests.py
```

**curl** (pick the script for your OS):
```bash
bash curl_tests.sh              # macOS/Linux
curl_tests_windows.bat          # Windows CMD
```

**Postman**: import `SmartDoc_AI.postman_collection.json` and
`SmartDoc_AI.postman_environment.json`.

**Agent loop, without a real Gemini key**: `tests/fakes.py` provides a
scripted `FakeGeminiClient` used to verify tool whitelisting and the
`MAX_STEPS` guard offline — see the compliance checklist for exact
results.

## Project structure

```
smartdoc_ai/
├── main.py                 # FastAPI app, /health, router assembly
├── database.py              # engine + Base (unchanged Session(engine) pattern)
├── models.py                 # Document ORM (+ priority, ai_summary)
├── schemas.py                 # Pydantic request/response models
├── settings.py                 # loads .env — GEMINI_API_KEY, GEMINI_MODEL, DATABASE_URL
├── routes/
│   ├── documents.py            # CRUD + /documents/upload
│   └── ai.py                    # /documents/{id}/analyze, /agent/ask
├── services/
│   ├── gemini_service.py         # Gemini API wrapper (analysis + agent step)
│   └── agent_service.py           # whitelisted tool-calling loop, MAX_STEPS=5
├── tests/fakes.py                  # FakeGeminiClient for offline agent verification
├── alembic.ini, alembic/            # migration config + versions
├── run_contract_tests.py             # automated HTTP contract check
├── curl_tests.sh / .bat               # manual curl smoke tests
├── SmartDoc_AI.postman_collection.json
├── SmartDoc_AI.postman_environment.json
├── ai_assisted_review.md               # Phase 6 prompt + diff + review notes
├── LAB6_COMPLIANCE_CHECKLIST.md          # PASS/FAIL per requirement
├── .env.example, .gitignore
└── requirements.txt
```

## Known limitation

This sandbox has no network access to `generativelanguage.googleapis.com`
and no real `GEMINI_API_KEY`. Everything **not** dependent on a live
Gemini call was executed and verified against a running server (see
`contract_matrix.md`, generated by `run_contract_tests.py`). The Gemini
call path itself was verified with a scripted fake client
(`tests/fakes.py`) to prove the tool-whitelisting and `MAX_STEPS` logic —
but the real network call to Gemini is **not verified** in this
environment. Run `python run_contract_tests.py` yourself with a real key
in `.env` to confirm the `/analyze` and `/agent/ask` "happy path".
